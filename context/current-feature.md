- Rate Limiting for Auth: Upstash-backed limits on every credentials auth flow, fixing the 2026-11-04 audit's High finding for sign-in and part of its Medium finding on per-address throttling. `@upstash/ratelimit@2` and `@upstash/redis@1` were added. The new `src/lib/rate-limit.ts` holds the five sliding-window rules (`signIn` 5 / 15 min keyed by IP + email, `register` 3 / 1 h by IP, `forgotPassword` 3 / 1 h by IP, `resetPassword` 5 / 15 min by IP, `resendVerification` 3 / 15 min by IP + email), a lazily created Redis client and one `Ratelimit` per rule under a `ratelimit:${name}` prefix, `rateLimit(name, key)` returning `{ success, remaining, reset }`, `getClientIp()` (first `x-forwarded-for` entry, then `x-real-ip`, then `unknown`), `getRetryAfterSeconds()` and `getRateLimitMessage()` ("Too many attempts. Please try again in X minutes."). It fails open: with the Upstash vars unset no check runs, a thrown error is logged and the attempt allowed, and the limiter's own `timeout` is 2 s with the Redis client cut to one retry so an outage can't stall auth for the default five-retry backoff. Sign-in is limited inside the credentials `authorize` in `src/auth.ts` from the `request` headers, before the user lookup and bcrypt, so one check covers both the `signInWithCredentials` action and a direct `POST /api/auth/callback/credentials`; over the limit it throws `TooManyAttempts` (a `CredentialsSignin` subclass with `code = RATE_LIMITED` from `src/lib/auth-redirect.ts` and a `reset` field), which Auth.js rethrows unchanged, so the action maps it to the message. `POST /api/auth/register` checks after validation and before the database lookup and returns 429 with `Retry-After`. The spec's forgot / reset / resend routes don't exist, so those limits live in the server actions in `src/actions/auth.ts` through a private `checkRateLimit()` reading `headers()`; forgot password is keyed by IP only so the blocked reply still reveals nothing about the email, and the resend check runs only while verification is on, since otherwise the action sends nothing.
